# Приватный доступ вне дома

Сервис самостоятельно не устанавливает VPN, не меняет Firewall/маршрутизацию и не открывает порты роутера. Ниже ручной сценарий для частной сети. Прямой HTTP через публичный интернет не используйте.

## Вариант: Tailscale на компьютере и телефоне

1. Самостоятельно установите VPN-клиент на Windows и телефон по [официальной инструкции Tailscale](https://tailscale.com/docs/how-to/quickstart). Подключите оба устройства к одной своей частной сети и убедитесь, что они видят друг друга. Не включайте публичный Funnel.
2. Узнайте частный VPN-IP Windows в клиенте или командой `tailscale ip -4`. Для Tailscale это обычно адрес из 100.64.0.0/10; сервис разрешает привязку к этому диапазону.
3. В `.env` установите `HOST=<VPN-IP-Windows>`, `PORT=8030`. Остановите предыдущий экземпляр и выполните `start-lan.ps1`. Конкретный VPN-IP ограничивает listener VPN-интерфейсом; `0.0.0.0` означает все интерфейсы.
4. В политике доступа вашей VPN разрешите только нужным устройствам TCP 8030 компьютера. В Windows Firewall при необходимости создайте узкое входящее правило с конкретным VPN-IP телефона как RemoteAddress и нужным адаптером/портом. Сетевой профиль VPN может отличаться от Private: сверяйте его вручную и ограничивайте адреса, а не открывайте весь профиль Public.
5. На телефоне отключите домашний Wi-Fi, включите мобильный интернет и VPN. Откройте `http://<VPN-IP-Windows>:8030` и введите API-ключ вручную. HTTP находится внутри защищённого VPN-канала. API-ключ обязателен и в VPN.
6. Убедитесь, что без VPN сервис с мобильного интернета недоступен; проверьте историю, обычный чат и RAG.

Альтернатива — уже настроенная частная WireGuard-сеть с теми же ограничениями доступа. Если выбран HTTPS reverse proxy, он должен слушать только нужный частный интерфейс, иметь доверенный сертификат и проксировать на `127.0.0.1:8030`. Конфигурация proxy здесь автоматически не создаётся. Не отключайте проверку сертификата на клиентах.

Ollama остаётся только на loopback; ни TCP 11434, ни API runtime через VPN не публикуются. На роутере не создавайте port forwarding. Доступ должен проходить через защищённый API приложения.

Проверка этого сценария требует второго устройства и действующей VPN-сети; локальный запрос с компьютера не подтверждает удалённый доступ.
